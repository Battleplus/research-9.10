# 导师讨论与资源确认清单

日期：2026-09-11
范围：A2 首篇论文的可证伪性、最小验证设计和资源核实。
状态：只做规划；不运行训练、实验、依赖安装、GPU/远程任务或论文写作。

## 1. A2 的可证伪研究假设

### 主假设

在协作多智能体强化学习中，当策略分布持续变化、团队结果依赖跨智能体交互、且候选轨迹池和任务偏好标签预算固定时：

> **经过当前策略覆盖度和协作影响校正的短期联合动力学 epistemic uncertainty，能够比奖励模型分歧、片段多样性、随机查询及其简单组合，更有效地选择能减少“协作决策歧义”的真实轨迹对。**

“更有效”必须在预先固定的任务偏好评估目标下定义，例如单位标签带来的留出任务偏好损失下降、策略与任务偏好的一致性，或独立协作任务指标的改善；不预设提升幅度。

### 三种不确定性不能混用

| 类型 | 它表示什么 | 可能的查询意义 | 不能直接推出什么 | 需要的诊断 |
|---|---|---|---|---|
| 模型知识不足（epistemic / knowledge uncertainty） | 训练数据覆盖不足、模型参数或结构对某种联合交互没有学会 | 候选行为的未来联合结果可能无法可靠预测，可能值得询问 | 预测分歧大就一定值得询问 | 集成/bootstrapping 分歧、数据覆盖度、重复训练稳定性、准确模型与学习模型对照 |
| 环境随机性（aleatoric uncertainty） | 环境本身的随机转移或观测噪声，即便知道模型也无法完全消除 | 可能需要重复采样或风险定义，但未必能由一次偏好标签消除 | 随机性大就代表人类任务偏好不明确 | 多次 rollout、条件方差/分布预测、随机性控制切片 |
| 奖励模型分歧 | 多个奖励/偏好模型对任务行为标签的预测不同 | 直接反映当前任务偏好预测的不一致，可能是强基线 | 它等同于动力学未知，或能说明哪一个智能体造成问题 | 与真实留出偏好、联合交互切片及动力学误差分别相关性/校准 |

因此，A2 不能把“下一状态预测误差大”直接写成“值得询问”。候选只有在联合模型的不确定性与协作决策变化、任务偏好分歧或查询后信息增益相联系时，才支持假设。

### 哪些条件下 A2 才有机会成立

- 任务结果包含不可约的交互依赖，不能由独立智能体分数简单相加解释。
- 队友策略或联合策略分布发生变化，使旧轨迹的任务偏好标签不再充分代表当前决策。
- 联合动力学模型能在候选片段上识别“哪种联合行动会改变后续协作结果”的知识缺口，而不是只识别环境噪声。
- 查询返回的仍是任务行为偏好（哪种行为更符合任务/用户目标）；动力学合理性偏好必须单独记录，不能作为同一标签。

## 2. 多智能体贡献与创新风险

A2 的多智能体贡献应落在可观察的协作失败现象上：

- 联合转移依赖多个智能体的动作组合，单个智能体局部不确定性无法表示交互项。
- 队友策略变化使同一个局部动作在不同队友行为下产生不同后果。
- 局部观测隐藏队友状态，协作失败可能延迟到后续时间才显现。
- 团队偏好标签无法直接指出哪个智能体或哪段交互造成了结果，但查询选择必须找到能区分协作决策的片段。

如果只是把单智能体查询方法的输入从 `s` 换成联合状态 `s_joint`，或把独立智能体不确定性相加，应明确标记为**创新性不足的高风险**。需要至少有一个可检验的 MARL-specific 机制：联合交互项、队友策略条件化、跨智能体动作组合的短期预测，或在队友策略变化下仍能识别查询价值；目前这些都只是待验证要求，不是已解决结论。

## 3. 最小验证设计（只列设计，不执行）

### 固定条件

1. 先由同一批环境交互生成固定候选轨迹池；所有查询方法从完全相同的池中选择片段对。
2. 固定每轮和全程任务偏好标签数、轨迹片段长度、候选池更新规则、下游偏好模型、策略学习器、随机种子集合和评估时点。
3. 固定环境交互预算；候选池扩充、世界模型训练/更新、主动查询重采样所用的额外交互必须单独计入，不能把更多 rollout 当作免费资源。
4. 记录选择器的推理时间、模型更新时间、显存/显式计算量或可复现的计算代理；世界模型集成规模和更新频率必须纳入总成本。
5. 评估使用留出任务偏好、独立协作任务指标、协作成功/失败切片、策略变化后的数据，以及跨地图或队友策略测试；不能只报告同一 script teacher 分布上的训练回报。

### 查询对照

- 随机查询；
- 奖励模型分歧/偏好模型 ensemble disagreement；
- 片段多样性；
- 当前策略覆盖度或策略似然；
- 简单组合（例如在相同输入和预算下对上述分数作固定、预注册的线性组合）；
- A2 候选：联合动力学 epistemic uncertainty + 当前策略覆盖度 + 协作影响/多样性；
- 诊断对照：无联合交互项的因子化动力学模型、仅独立智能体不确定性、准确动力学模型与学习动力学模型。

### 支持、暂停和重定义标准

**支持假设的结果：** 第一层在同一候选池、标签数、环境交互量和下游学习设置下完整报告计算成本，第二层另行匹配总计算预算检验成本收益；若 A2 在留出任务偏好或独立协作目标上更快达到同一质量；优势集中在交互依赖/队友策略变化切片；联合交互项消融后优势消失；且动力学不确定性与任务查询价值相关，而不是只与下一状态预测误差相关。

**应暂停或拒绝 A2 的结果：** 奖励模型分歧、随机/多样性或简单组合已经同样有效；优势只来自更多候选片段、标签、参数、模拟或计算；联合模型只预测环境随机性或动力学误差，不能预测任务偏好查询价值；去掉联合交互项仍无差异；或真实/留出任务偏好无法获得而 script/LLM proxy 的结论不稳定。

**应重新定义问题的结果：** 若世界模型只改善动力学校准而不改善任务偏好查询，应改写为模型不确定性校准/主动动力学学习问题，而不是 A2；若查询价值不明显但 agent-time 分解有稳定、可验证目标，才考虑转入 A1；不能因为 A2 失败就自动切换到 B。

## 5. A2 当前推进边界

### 继续推进条件

- 能拿到可复现的联合轨迹/转移 schema 和一个可独立解释的协作任务指标。
- 能明确任务行为偏好标签来源，并把 script/LLM proxy 与真实人类标签的结论边界写清楚。
- 能复现或审计世界模型代码、配置和不确定性定义，且有 4060 可承受的最小诊断路径。
- 导师认可“查询价值”是目标瓶颈，并同意固定候选池、匹配预算和多智能体消融作为基本验证标准。

### 暂停条件

- 关键资源无法确认，尤其是联合转移、环境版本、标签权限或独立任务指标。
- 最后查新仍发现同一 cooperative-MARL 联合动力学查询机制，或导师无法支持数据/评估协议。
- 设计无法把知识不足、环境随机性和奖励模型分歧分开。
- 只能依靠增加模拟、标签或计算获得表面提升，或无法说明 MARL-specific 贡献。

### 当前未知项

1. 用户已有世界模型/PbRL 实现的真实成熟度、可复现性与许可证边界。
2. 是否有真实人类任务行为偏好；若没有，script/LLM proxy 能支持到什么结论仍待导师确认。
3. 是否能记录完整联合状态转移、队友策略版本和跨策略评估数据。
4. A2 的联合交互信息是否能在控制成本后带来独立于奖励模型分歧的查询价值。
5. 目标学校 A−/A 口径对应的具体投稿范围与证据要求。
