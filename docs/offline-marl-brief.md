# 任务结构先验与离线多智能体泛化

> 状态：保留为早期备选资料，下文的排序或主线称谓属于原方案。当前优先决策以[连续研究路线](continuous-research-roadmap.md)为准。

已知资源为 RTX 4060 与 H200，目标按现有成果认定方案优先 A−／A。实验语境限定仓储协作、协同搬运与资源收集等通用民用任务。

工作题目：**《不完备任务结构先验下离线多智能体组合泛化与负迁移控制》**。题目是研究假设，不代表新颖性已经证明。

**研究目标**

验证两个问题：当离线数据只覆盖部分协作组合，结构先验在什么条件下真正有效；当结构先验错误或过时，是否能够减少对错误结构的依赖，避免负迁移。

预期交付可以是新方法及机制分析，也可以是系统性的适用边界研究。不能预先约定一定得到正向提升。

**必须比较的已有研究**

| 来源 | 已涉及的问题 | 对本题的限制 |
|---|---|---|
| [ICLR 2025：Low Interaction Rank](https://proceedings.iclr.cc/paper_files/paper/2025/hash/9a55d80ab23017cf7094824c03a25843-Abstract-Conference.html) | 离线多智能体结构与分布偏移 | 不能仅宣称结构化 critic 更鲁棒 |
| [2026：OOD Sequence Models](https://arxiv.org/abs/2609.03667) | 离线多智能体跨任务泛化与容量／数据关系 | 不能仅宣称多任务序列模型能泛化 |
| [AISTATS 2025：Representational Penalization](https://proceedings.mlr.press/v258/bose25a.html) | 离线迁移、不完整覆盖、表征不确定性 | 不确定性驱动迁移本身已有方法 |
| [IJCAI 2025：Variational Offline Multi-agent Skill Discovery](https://www.ijcai.org/proceedings/2025/538) | 离线协作技能发现与迁移 | 不能仅用“子技能组合”作贡献 |
| [MangoBench](https://github.com/SYSU-SAIL/mangobench-locomotion) | 多智能体目标条件离线学习基准 | 可以借鉴实验任务，不可混淆其协议与自行设计的结构泛化协议 |

还需专项检索：task graph uncertainty、misspecified structural priors、negative transfer、compositional offline MARL。当前证据支持值得做 pilot，不支持“首次提出”的表述。

**三个候选点子，先验证一个**

1. **先验可靠性控制。** 当任务依赖信息与离线轨迹支持冲突时，降低结构引导的权重。重点检验是否优于固定权重、验证集调权和更大模型，不能靠引入额外测试标签获益。
2. **组合覆盖诊断。** 区分“单个子任务都见过但联合组合没见过”与“关键子任务也没见过”，检验结构先验收益是否受覆盖条件支配。优先作为诊断实验，避免先造复杂网络。
3. **可部署结构压缩。** 训练时利用结构，执行时仅保留局部可用的表示；核对分散执行下是否仍有收益。若依赖隐含的全局状态，就不能宣称纯局部执行。

首轮优先验证点子 2，再决定是否有必要实现点子 1。点子 3 后置，避免第一次实验同时改表示、价值函数、策略和通信机制。

**实验路线**

第一步，用受控小型协作环境隔离变量。数据预先固定，训练只读取数据；评估时运行环境不等于允许在线训练。若采用验证环境交互，明确记录并对所有方法保持同等规则；不能声称整个流程绝无额外交互。

第二步，使用 [OG-MARL](https://github.com/instadeepai/og-marl) 可获得的数据／基线核对实现，或选择合适的 MangoBench 协同操作任务。现有数据未必带有需要的任务依赖标签，应先确认字段和标注来源。自行采集数据时，收集策略、训练成本与版本也计入资源说明。

第三步，H200 扩展到至少两个有差异的任务族及完整消融。不能把同一环境的很多随机种子等同多个独立任务族。图结构生成、缺失或错误注入方式要具有可解释含义，不能只构造对拟议方法有利的扰动。

**公平基线**

包括适用的行为克隆、成熟离线多智能体方法、相近容量的序列模型、硬结构先验模型、随机／扰乱结构对照以及拟议方法。最接近的低交互秩方法仅在设定适用时纳入直接比较；否则在相关工作中解释差异。MAPPO 可作为在线数据生成或额外参照，但不能作为唯一基线来证明离线方法优势。

公开论文若没有可获得代码，准确标为“依据论文独立复现”，记录差异。不能把未跑通的强基线默默删去。

**主要实验因素**

| 因素 | 要分清的条件 |
|---|---|
| 数据覆盖 | 子任务覆盖、组合覆盖、联合动作支持 |
| 数据质量 | 不同质量轨迹及比例，不能只用专家数据 |
| 结构可靠性 | 正确、不完整、有错、不提供结构 |
| 泛化 | 新组合、新布局、其他适用任务变化分别报告 |
| 资源 | 相同数据、交互、调参预算；另报告容量和计算量 |

主指标为真实任务成功率或任务规定回报，另报告负迁移任务比例、结构错误敏感性、训练与推理开销。适用时报告安全／约束指标，但不把它们伪装为原 benchmark 固有指标。

**资源分配**

4060 运行数据检查、环境单测、短训练和作图。H200 运行正式训练、等容量对照和多种子实验。先用一个中等基线测吞吐、显存和端到端时间，再计算“配置数 × 任务数 × 种子数 × 单次时间”。不能根据显卡名称虚构总耗时。

H200 可用不等于需要训练最大模型。先验证结构信号是否存在，再扩模型容量，专门检查收益是否只是更多参数带来的。

**阶段安排与停止条件**

第 1 周：完成最接近工作对照、任务和数据审计、基线短运行。若数据没有需要的结构信息且无法合理构建，不进入大规模训练。

第 2—3 周：完成受控覆盖与结构错误实验。若任务差异可被简单调参解释，或只在特定人工条件有效，缩小主张或改题。

后续阶段：根据 pilot 选择方法改进，扩展任务族和种子，完成消融和独立重跑。通常应按数周到数月规划，不能承诺一次自动运行后即可投稿。

停止条件：已有等价方法；结构依赖测试真值；只赢明显弱基线；同计算量不再有效；效果对随机种子不稳定；完整环境验证与离线诊断相矛盾。
